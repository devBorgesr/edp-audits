# Beta feedback — DPOLens Audit #001

Thank you for allowing an independent review of the public DPOLens retrieval artifacts.

The audit intentionally does **not** present “the reranker performs worse” as a new discovery. That aggregate behavior was already documented upstream.

The beta question is narrower: did the independent query-level decomposition or forensic follow-up reveal something useful, incorrect, or worth testing next?

## Short feedback is enough

Please answer whichever items are useful:

1. **Already known** — which findings were already known before this audit?
2. **New but not useful** — did anything new fail to change your next step?
3. **New and useful** — did anything make a debugging or evaluation decision clearer?
4. **Incorrect / missing context** — did the audit misunderstand any DPOLens retrieval or evaluation semantics?
5. **Next experiment** — would the duplicate-candidate / reranking observation be worth testing, or is there a better explanation we should investigate?
6. **Practical value** — would this kind of external audit save meaningful debugging/evaluation time?
7. **Optional commercial signal** — what additional evidence or output, if any, would make an external audit like this worth paying for?

Negative feedback is as useful as positive feedback. A correction is a successful beta outcome if it improves the audit method.
